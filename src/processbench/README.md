# ProcessBench → Harbor Adapter

## Overview

This adapter converts [ProcessBench](https://github.com/QwenLM/ProcessBench) (ACL 2025) into Harbor tasks. Each task shows the agent a competition-style math problem together with a step-by-step solution split into indexed paragraphs, and asks for the index of the **earliest erroneous paragraph**, or `-1` if every paragraph is correct.

- **Size:** 3,400 tasks, one per ProcessBench item: `gsm8k` (400), `math` (1,000), `olympiadbench` (1,000), `omnimath` (1,000). No items are excluded.
- **Source:** Hugging Face dataset [`Qwen/ProcessBench`](https://huggingface.co/datasets/Qwen/ProcessBench), pinned to revision `3bdcd5371ed567559a78f559c01c13a6deee7604`. The prompt and grading follow the upstream code at commit [`e802463`](https://github.com/QwenLM/ProcessBench/tree/e8024636bcabdf8bd514440551b531d3f90dd18b): [`code/run_eval.py`](https://github.com/QwenLM/ProcessBench/blob/e8024636bcabdf8bd514440551b531d3f90dd18b/code/run_eval.py) and [`code/templates/critique_template.txt`](https://github.com/QwenLM/ProcessBench/blob/e8024636bcabdf8bd514440551b531d3f90dd18b/code/templates/critique_template.txt).
- **Domain / language:** mathematical reasoning, English.
- **Main adaptation:** the original harness calls the model directly via vLLM. Here the same prompt is given to a CLI agent, with one appended sentence asking it to write the answer to `answer.txt` (see [Notes & Caveats](#notes--caveats)).

## What is ProcessBench?

ProcessBench ([paper](https://huggingface.co/papers/2412.06559)) measures whether a model can identify process errors in mathematical reasoning, rather than only checking the final answer. Solutions were generated by 12 Qwen and Llama models and annotated by human experts with the index of the earliest erroneous step. 521 of the 3,400 solutions reach the correct final answer despite containing a process error, so final-answer checking alone cannot solve the benchmark.

The original evaluation (`code/run_eval.py`) extracts the last `\boxed{}` from the model output, converts it to an integer, and counts an exact match with the label. For each subset it reports accuracy on erroneous samples (`label != -1`), accuracy on correct samples (`label == -1`), and their harmonic mean (**F1**), the headline metric.

## Adapter Features

- **Pinned data download:** fetches the four subset JSON files from Hugging Face at a fixed revision (honours `HF_ENDPOINT` for mirrors, cached under `~/.cache/harbor-processbench/`), or reads local files via `--data-dir`.
- **Prompt fidelity:** `instruction.md` is the original `critique_template.txt` filled with the same `<paragraph_i>` tagging as `prepare_input_boxed()`, byte-for-byte, plus one output-location sentence.
- **Same grading as upstream:** `tests/grade.py` reuses the original `extract_answer` regex, `int()` conversion, and exact match. Reward is `1` or `0`.
- **Subset-level F1:** `grade.py` also writes `/logs/verifier/metrics.json` (`id`, `subset`, `label`, `prediction`, `match`). `aggregate_metrics.py` regroups a job's trials into the original per-subset error accuracy, correct accuracy, and F1, plus the average F1.
- **Parity split:** `--split parity` generates a 200-task stratified sample (50 per subset, keeping each subset's error/correct ratio, seed 42).
- **Oracle:** `solve.sh` writes `\boxed{<label>}` to `/app/answer.txt`.
- **Lightweight environment:** text-only task. The image is a stock Ubuntu 24.04 base with `WORKDIR /app` and no extra dependencies.
- **Isolation:** upstream generates offline with no tools or network, so during the agent run only the LLM APIs (`api.openai.com`, `api.anthropic.com`) are reachable (`[agent] network_mode = "allowlist"`). Grading runs in a separate verifier container (`environment_mode = "separate"`, no network) built from `tests/Dockerfile`. Only `/app/answer.txt` is copied into it, so the agent never sees `ground_truth.<id>.json` or the grader, and `test.sh` clears any existing reward/metrics files before grading.
- **Unique label file name:** the label is stored as `tests/ground_truth.<id>.json`, and `grade.py` requires exactly one such file whose `id` matches its name. Harbor builds every verifier image from a context directory named `tests`, and Docker/BuildKit can reuse a file from another task's context when its path, size and mtime match, which would give a verifier another task's label. A unique file name rules this out.

## Run Evaluation / Harness

### Running with Datasets Registry

After the dataset is published:

```bash
# Oracle (reference answers)
harbor run -d qwen/processbench

# A specific agent and model
harbor run -d qwen/processbench -a <agent_name> -m "<model_name>"

# Parity subset (once published under the `parity` tag)
harbor run -d qwen/processbench@parity -a <agent_name> -m "<model_name>"
```

### Using Job Configurations

From the repository root, after [creating the task directories](#usage-create-task-directories):

```bash
# Full dataset (oracle by default; uncomment another agent in the YAML to switch)
harbor run -c src/processbench/run_processbench.yaml

# Parity subset
harbor run -c src/processbench/run_processbench_parity.yaml -a <agent_name> -m "<model_name>"

# Without a config file
harbor run -p datasets/processbench -a <agent_name> -m "<model_name>"
```

Results are saved in `jobs/`. Harbor's mean reward is the overall exact-match accuracy. To get ProcessBench's metrics, run:

```bash
cd src/processbench
uv run python -m processbench.aggregate_metrics ../../jobs/<job_name> \
  --dataset-dir ../../datasets/processbench --output results.json
```

This prints `error acc`, `correct acc`, and `f1` for each subset, as `run_eval.py` does, plus the average F1. Each trial's final `result.json` must record trial and verifier completion, a binary verifier reward consistent with `metrics.json`, and the same task ID. Provider errors (including server errors, rate limits, account usage limits, authentication, and network failures) and unclassified exceptions are listed and cause a non-zero exit without reporting F1, even when grading produced metrics. They are not counted as model mistakes or silently removed from the denominator.

The scoring policy retains finished, scored attempts with `AgentTimeoutError` (the allotted time expired), `OutputTokenExceededError`, `ContextWindowExceededError`, or `AgentSafetyRefusalError` as valid experiment outcomes. Their verifier scores are preserved. Wrong, missing, or unparsable answers in valid attempts score 0 and count as wrong. With `--dataset-dir`, any expected task without metrics also prevents F1: an incomplete job is not a full parity result, so fix or rerun those trials first. Aggregate each run (job) separately, with one attempt per task.

### Running Individual Trial

```bash
harbor trial start -p datasets/processbench/processbench-gsm8k-0
harbor trial start -p datasets/processbench/processbench-gsm8k-0 -a <agent_name> -m "<model_name>"
```

## Usage: Create Task Directories

```bash
cd src/processbench
uv sync
uv run processbench --output-dir ../../datasets/processbench                 # all 3,400 tasks
uv run processbench --split parity --output-dir ../../datasets/processbench_parity  # 200-task parity subset
```

Available flags:
- `--output-dir`: where to write tasks (default: `datasets/processbench` at the repository root)
- `--limit`: generate only the first N tasks after filtering
- `--overwrite`: overwrite existing task directories
- `--task-ids`: only generate these items; accepts upstream IDs (`gsm8k-0`) or directory names (`processbench-gsm8k-0`)
- `--split {full,parity}`: full dataset or the stratified parity subset
- `--subsets`: restrict to some of `gsm8k`, `math`, `olympiadbench`, `omnimath`
- `--data-dir`: read `<subset>.json` files from a local directory instead of downloading

### Oracle Verification

On 2026-11-23, a full-dataset oracle run of adapter commit `1467787` passed all 3,400 tasks: 400 gsm8k, 1,000 math, 1,000 olympiadbench, and 1,000 omnimath. That commit stores each task's label as `tests/ground_truth.<id>.json` (see [Adapter Features](#adapter-features)), and the adapter code, task template and tests are unchanged since. A `nop` control (no answer written) receives reward 0.

## Comparison with Original Benchmark (Parity)

Both sides ran `codex@0.161.0` with `gpt-5.6-terra` (reasoning effort `xhigh`) on the 200-task parity subset, 3 runs each (2026-11-22 and 2026-11-23). Scores are mean ± sample SEM over the 3 runs; the individual run scores are in `parity_experiment.json`.

| Agent | Model | Metric | Runs | Dataset Size | Original (mean ± SEM) | Harbor (mean ± SEM) |
|-------|-------|--------|------|--------------|-----------------------|---------------------|
| codex@0.161.0 | gpt-5.6-terra | Average F1 | 3 | 200 (5.9% of full set) | 78.48 ± 0.95 | 78.78 ± 0.38 |
| codex@0.161.0 | gpt-5.6-terra | Average accuracy | 3 | 200 (5.9% of full set) | 79.17 ± 0.60 | 79.00 ± 0.29 |
| codex@0.161.0 | gpt-5.6-terra | Average error accuracy | 3 | 200 (5.9% of full set) | 77.15 ± 0.44 | 75.71 ± 0.49 |
| codex@0.161.0 | gpt-5.6-terra | Average correct accuracy | 3 | 200 (5.9% of full set) | 81.00 ± 1.59 | 83.44 ± 0.35 |

Metric definitions: **error accuracy** is exact-match accuracy on samples with a process error (`label != -1`), **correct accuracy** is accuracy on fully correct samples (`label == -1`), **F1** is their harmonic mean, and **accuracy** is exact-match accuracy over all samples. The averages are over the four subsets (50 samples each). Average F1 is the headline number reported by upstream's `run_eval.py`.

| math | 80.39 ± 0.83 | 80.39 ± 0.83 | 82.00 ± 1.15 | 82.00 ± 1.15 | 86.67 ± 1.92 | 86.67 ± 1.92 | 75.00 ± 0.00 | 75.00 ± 0.00 |
| olympiadbench | 78.36 ± 0.56 | 77.78 ± 1.14 | 77.33 ± 0.67 | 76.67 ± 1.33 | 74.75 ± 1.01 | 73.74 ± 2.02 | 82.35 ± 0.00 | 82.35 ± 0.00 |
| omnimath | 70.90 ± 3.50 | 74.72 ± 1.75 | 72.00 ± 2.31 | 73.33 ± 1.33 | 72.81 ± 1.75 | 71.93 ± 0.88 | 69.44 ± 5.56 | 77.78 ± 2.78 |

The run-score ranges of the two sides overlap for all 20 reported metrics, so the sides match under the repository's [matching criterion](../../docs/adapters.mdx#matching-criterion). The parity subset has only 12 to 24 fully correct samples per subset, so correct accuracy moves in steps of 4 to 8 points per item and is the noisiest metric (for example omnimath original-side runs range from 58.3 to 75.0).

A per-task comparison of all 200 items (original 3 runs against Harbor 3 runs) shows no one-sided pattern: 186 items have the same number of correct runs on both sides, the other 14 split 8 in favor of the original side and 6 in favor of Harbor, and no item is answered correctly in all runs on one side and in none on the other. Average accuracy differs by 0.2 points.

**Setup:**
- **Original side:** [`XBsleepy/ProcessBench@codex-backend`](https://github.com/XBsleepy/ProcessBench/tree/codex-backend), a fork of `QwenLM/ProcessBench` that adds `--backend codex` to `code/run_eval.py`. It sends the same prompt (including the appended output sentence) to `codex exec` in a fresh working directory and `CODEX_HOME`, reads `answer.txt`, and then uses the unchanged `extract_answer` and F1 code.
- **Harbor side:** `harbor run -c src/processbench/run_processbench_parity.yaml -a codex -m <model>`, then `aggregate_metrics.py`. Harbor 0.21.0 on Daytona (1 CPU and 2 GB per sandbox, as declared by the tasks), 32 concurrent trials, unmodified adapter output, codex installed by Harbor.
- **Subset:** `--split parity`, 50 items per subset, stratified by error/correct (seed 42). The fork's `code/parity_ids.txt` lists the same 200 IDs.
- **Agent and model:** `codex@0.161.0` and `gpt-5.6-terra` on both sides, reasoning effort `xhigh`, through an OpenAI-compatible relay.
- **Identical prompt, one asymmetry:** the task prompt sent to codex is byte-identical on all 200 items. codex adds its own environment context to the first message, which differs between sides (working directory `/tmp/processbench-codex-*/work` against `/app`, timezone `Asia/Shanghai` against `UTC`).
- **Retries:** Harbor retries only infrastructure errors (`retry.max_retries = 2`). One run had 5 retries, all `AgentSetupTimeoutError` during the codex installation, and no trial ended with an error.

Links: [original benchmark](https://github.com/QwenLM/ProcessBench), [fork with codex backend](https://github.com/XBsleepy/ProcessBench/tree/codex-backend), [adapter PR](https://github.com/harbor-framework/adapters/pull/70), [dataset PR](https://github.com/harbor-framework/harbor-datasets/pull/292). Parity-experiments PR: pending.

Reproduction:

- **Original side** ([`XBsleepy/ProcessBench@codex-backend`](https://github.com/XBsleepy/ProcessBench/tree/codex-backend); see its README for options). Install `codex@0.161.0` and put your provider settings in a `config.toml`:
  ```bash
  git clone -b codex-backend https://github.com/XBsleepy/ProcessBench.git && cd ProcessBench/code
  python run_eval.py --backend codex --model gpt-5.6-terra --codex_config <config.toml> \
    --ids_file parity_ids.txt --n_concurrent 8 --output_dir <out_dir>
  ```
  The data is downloaded from the Hugging Face dataset `Qwen/ProcessBench`. Run it three times with different `--output_dir` values.
- **Harbor side** (Harbor 0.21.0, oracle-verified). Edit `config` in `run_processbench_parity.yaml` to point at your codex `config.toml`, then:
  ```bash
  cd src/processbench && uv run processbench --split parity --output-dir ../../datasets/processbench_parity && cd ../..
  uvx --from harbor==0.21.0 harbor run -c src/processbench/run_processbench_parity.yaml \
    --allow-agent-host <your provider host> --env-file <file with DAYTONA_API_KEY and your model API key>
  cd src/processbench && uv run python -m processbench.aggregate_metrics ../../jobs/<job_name> \
    --dataset-dir ../../datasets/processbench_parity
  ```
  The agent network allowlist covers only the OpenAI and Anthropic APIs, so a provider host such as a relay has to be added with `--allow-agent-host`. The reported runs used Daytona. On a local Docker host, set `environment.type: docker` and lower `n_concurrent_trials` to about 8: every trial installs codex in its own container, so higher concurrency only competes for CPU.

## Notes & Caveats

- **Agent-based instead of direct LLM evaluation.** The original harness generates with vLLM (`temperature=0`, `seed=42`, `max_tokens=8192`) from a single user message. Here a CLI agent receives the same prompt, so scores are not directly comparable with the paper's tables. Parity compares the same agent on both sides.
- **Prompt modification:** one sentence is appended to the original critique prompt on both sides: ``Write your final answer to the file `answer.txt` in the current working directory, in the form \boxed{index}.`` The task image sets `WORKDIR /app`, and the verifier reads `/app/answer.txt`.
- **Answer parsing is unchanged from upstream,** including its limits. The regex `\\boxed\{([^}]*)\}` does not handle nested braces (`\boxed{\text{2}}` fails to parse), and a bare number without `\boxed{}` scores 0.
- **F1 is a dataset-level metric.** Per-task reward is exact match. F1 has to be computed from a complete job with `aggregate_metrics.py`. Harbor's built-in mean reward is plain accuracy, which is dominated by the larger `label != -1` group.
- **Not adapted:** the PRM evaluation path (`run_eval_prm_rlhflow.py`, which queries a process reward model one step at a time for a single `+`/`-` token) and the majority-voting mode (`--use_voting`). Neither maps onto a single agent trial.
- **Environment context differs slightly between the two sides.** Codex adds its own environment context to the first message (working directory and timezone). On the original side it is `/tmp/processbench-codex-*/work` and `Asia/Shanghai`, on the Harbor side `/app` and `UTC`. The task prompt itself is byte-identical on both sides.
- **Process errors with correct final answers:** 521 items have a correct final answer but a labelled process error (`final_answer_correct = true`, `label != -1`). This is intended by the benchmark.

## Installation / Prerequisites

- Docker installed and running (the verifier is built from `tests/Dockerfile`), or a `DAYTONA_API_KEY` to run on Daytona (`environment.type: daytona`, used for the reported parity runs)
- Harbor CLI: `uv tool install harbor`
- Adapter environment (standard library only, no extra dependencies):
  ```bash
  cd src/processbench
  uv sync
  ```
- Network access to Hugging Face for the first run, or set `HF_ENDPOINT` (e.g. `https://hf-mirror.com`), or pass `--data-dir` with local copies of the four JSON files.
- API keys for the agent/model you run (e.g. `OPENAI_API_KEY` for codex). If the agent talks to an endpoint other than `api.openai.com` / `api.anthropic.com` (relay, proxy, other provider), allow it with `harbor run --allow-agent-host <host>`, or the agent's requests are blocked.

## Troubleshooting

- **Download fails or hangs:** set `HF_ENDPOINT=https://hf-mirror.com`, or download the dataset with `hf download Qwen/ProcessBench --repo-type dataset --revision 3bdcd5371ed567559a78f559c01c13a6deee7604 --local-dir <dir>` and pass `--data-dir <dir>`.
- **Reward 0 with an apparently correct answer:** check `verifier/test-stdout.txt` in the trial directory. It prints the parsed prediction. A common cause is a missing `\boxed{}` or `answer.txt` written outside `/app` (only `/app/answer.txt` is copied to the verifier).
- **Agent fails with connection errors:** its API host is not in the allowlist; pass `--allow-agent-host <host>`.
- **`AgentSetupTimeoutError` or `NonZeroAgentExitCodeError` while installing codex:** the in-container install of nodejs, npm and codex can time out or fail under high concurrency or a slow network. Keep `retry.max_retries` at 2 (Harbor retries only infrastructure errors), and on a local Docker host lower `n_concurrent_trials`. If the host cannot reach `archive.ubuntu.com`, mount a mirror `sources.list` into the container with `environment.mounts`.
- **`aggregate_metrics.py` reports duplicate trials:** the job used more than one attempt per task. Aggregate jobs with `n_attempts: 1`, one run at a time.
