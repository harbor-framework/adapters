# ProcessBench → Harbor Adapter

## Overview

This adapter converts [ProcessBench](https://github.com/QwenLM/ProcessBench) (ACL 2025) into Harbor tasks. Each task shows the agent a competition-style math problem together with a step-by-step solution split into indexed paragraphs, and asks for the index of the **earliest erroneous paragraph**, or `-1` if every paragraph is correct.

- **Size:** 3,400 tasks, one per ProcessBench item: `gsm8k` (400), `math` (1,000), `olympiadbench` (1,000), `omnimath` (1,000). No items are excluded.
- **Source:** Hugging Face dataset [`Qwen/ProcessBench`](https://huggingface.co/datasets/Qwen/ProcessBench), pinned to revision `3bdcd5371ed567559a78f559c01c13a6deee7604`. The prompt and grading follow the upstream code at commit [`e802463`](https://github.com/QwenLM/ProcessBench/tree/e8024636bcabdf8bd514440551b531d3f90dd18b): [`code/run_eval.py`](https://github.com/QwenLM/ProcessBench/blob/e8024636bcabdf8bd514440551b531d3f90dd18b/code/run_eval.py) and [`code/templates/critique_template.txt`](https://github.com/QwenLM/ProcessBench/blob/e8024636bcabdf8bd514440551b531d3f90dd18b/code/templates/critique_template.txt).
- **Domain / language:** mathematical reasoning, English.
- **Main adaptation:** the original harness calls the model directly via vLLM. Here the same prompt is given to a CLI agent, with one appended sentence asking it to write the answer to `answer.txt` (see [Notes & Caveats](#notes--caveats)).

## What is ProcessBench?

ProcessBench ([paper](https://huggingface.co/papers/2412.06559)) measures whether a model can identify process errors in mathematical reasoning, rather than only checking the final answer. Solutions were generated by 12 Qwen and Llama models and annotated by human experts with the index of the earliest erroneous step. 521 of the 3,400 solutions reach the correct final answer despite containing a process error, so final-answer checking alone cannot solve the benchmark.

The original evaluation (`code/run_eval.py`) extracts the last `\boxed{}` from the model output, converts it to an integer, and counts an exact match with the label. For each subset it reports accuracy on erroneous samples (`label != -1`), accuracy on correct samples (`label == -1`), and their harmonic mean (**F1**), the headline metric.

## Adapter Features

- **Pinned data download:** fetches the four subset JSON files from Hugging Face at a fixed revision (honours `HF_ENDPOINT` for mirrors, cached under `~/.cache/harbor-processbench/`), or reads local files via `--data-dir`.
- **Prompt fidelity:** `instruction.md` is the original `critique_template.txt` filled with the same `<paragraph_i>` tagging as `prepare_input_boxed()`, byte-for-byte, plus one output-location sentence.
- **Same grading as upstream:** `tests/grade.py` reuses the original `extract_answer` regex, `int()` conversion, and exact match. Reward is `1` or `0`.
- **Subset-level F1:** `grade.py` also writes `/logs/verifier/metrics.json` (`id`, `subset`, `label`, `prediction`, `match`). `aggregate_metrics.py` regroups a job's trials into the original per-subset error accuracy, correct accuracy, and F1, plus the average F1.
- **Oracle:** `solve.sh` writes `\boxed{<label>}` to `/app/answer.txt`.
- **Lightweight environment:** text-only task. The image is a stock Ubuntu 24.04 base with `WORKDIR /app` and no extra dependencies.

## Run Evaluation / Harness

### Running with Datasets Registry

After the dataset is published:

```bash
# Oracle (reference answers)
harbor run -d qwen/processbench

# A specific agent and model
harbor run -d qwen/processbench -a <agent_name> -m "<model_name>"

```

### Using Job Configurations

From the repository root, after [creating the task directories](#usage-create-task-directories):

```bash
# Full dataset (oracle by default; uncomment another agent in the YAML to switch)
harbor run -c src/processbench/run_processbench.yaml

# Without a config file
harbor run -p datasets/processbench -a <agent_name> -m "<model_name>"
```

Results are saved in `jobs/`. Harbor's mean reward is the overall exact-match accuracy. To get ProcessBench's metrics, run:

```bash
cd src/processbench
uv run python -m processbench.aggregate_metrics ../../jobs/<job_name> \
  --dataset-dir ../../datasets/processbench --output results.json
```

This prints `error acc`, `correct acc`, and `f1` for each subset, as `run_eval.py` does, plus the average F1. Wrong, missing, or unparsable answers score 0 and count as wrong. With `--dataset-dir`, tasks without a verifier result (agent, infrastructure, or verifier failures) are listed and the script exits non-zero without reporting F1: an incomplete job is not a full parity result, so fix or rerun those trials first. Aggregate each run (job) separately, with one attempt per task.

### Running Individual Trial

```bash
harbor trial start -p datasets/processbench/processbench-gsm8k-0
harbor trial start -p datasets/processbench/processbench-gsm8k-0 -a <agent_name> -m "<model_name>"
```

## Usage: Create Task Directories

```bash
cd src/processbench
uv sync
uv run processbench --output-dir ../../datasets/processbench                 # all 3,400 tasks
```

Available flags:
- `--output-dir`: where to write tasks (default: `datasets/processbench` at the repository root)
- `--limit`: generate only the first N tasks after filtering
- `--overwrite`: overwrite existing task directories
- `--task-ids`: only generate these items; accepts upstream IDs (`gsm8k-0`) or directory names (`processbench-gsm8k-0`)
- `--subsets`: restrict to some of `gsm8k`, `math`, `olympiadbench`, `omnimath`
- `--data-dir`: read `<subset>.json` files from a local directory instead of downloading

### Oracle Verification

With Harbor 0.21.0 and Docker, the oracle agent scores 100% on all 3,400 tasks (0 exceptions). `aggregate_metrics.py` reports error acc, correct acc, and F1 of 100.0 for every subset, with 0 missing tasks. Running the `nop` agent (no answer written) gives reward 0, which confirms the verifier does not pass empty submissions.

## Notes & Caveats

- **Agent-based instead of direct LLM evaluation.** The original harness generates with vLLM (`temperature=0`, `seed=42`, `max_tokens=8192`) from a single user message. Here a CLI agent receives the same prompt, so scores are not directly comparable with the paper's tables.
- **Prompt modification:** the adapter appends one sentence to the original critique prompt: ``Write your final answer to the file `answer.txt` in the current working directory, in the form \boxed{index}.`` The task image sets `WORKDIR /app`, and the verifier reads `/app/answer.txt`.
- **Answer parsing is unchanged from upstream,** including its limits. The regex `\\boxed\{([^}]*)\}` does not handle nested braces (`\boxed{\text{2}}` fails to parse), and a bare number without `\boxed{}` scores 0.
- **F1 is a dataset-level metric.** Per-task reward is exact match. F1 has to be computed from a complete job with `aggregate_metrics.py`. Harbor's built-in mean reward is plain accuracy, which is dominated by the larger `label != -1` group.
- **Not adapted:** the PRM evaluation path (`run_eval_prm_rlhflow.py`, which queries a process reward model one step at a time for a single `+`/`-` token) and the majority-voting mode (`--use_voting`). Neither maps onto a single agent trial.
- **Process errors with correct final answers:** 521 items have a correct final answer but a labelled process error (`final_answer_correct = true`, `label != -1`). This is intended by the benchmark.

## Installation / Prerequisites

- Docker installed and running
- Harbor CLI: `uv tool install harbor`
- Adapter environment (standard library only, no extra dependencies):
  ```bash
  cd src/processbench
  uv sync
  ```
- Network access to Hugging Face for the first run, or set `HF_ENDPOINT` (e.g. `https://hf-mirror.com`), or pass `--data-dir` with local copies of the four JSON files.
- API keys for the agent/model you run (e.g. `OPENAI_API_KEY` for codex).

## Troubleshooting

- **Download fails or hangs:** set `HF_ENDPOINT=https://hf-mirror.com`, or download the dataset with `hf download Qwen/ProcessBench --repo-type dataset --revision 3bdcd5371ed567559a78f559c01c13a6deee7604 --local-dir <dir>` and pass `--data-dir <dir>`.
- **Reward 0 with an apparently correct answer:** check `verifier/test-stdout.txt` in the trial directory. It prints the parsed prediction. A common cause is a missing `\boxed{}` or `answer.txt` written outside `/app`.
- **`aggregate_metrics.py` reports duplicate trials:** the job used more than one attempt per task. Aggregate jobs with `n_attempts: 1`, one run at a time.
