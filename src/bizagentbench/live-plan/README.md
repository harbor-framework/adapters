## 两类实验与顺序

一次 episode 指一题在一侧的完整业务对话，其中通常包含多次 API 请求。

| 阶段 | 角色与题目 | 规模 | 进入下一步的条件 |
| --- | --- | --- | --- |
| A0 免费准备 | 固定源码版本、真实客户入口、协议兼容检查、费用计量与隔离检查 | 0 次模型调用 | 准备可审阅配置，维持禁用 |
| A1 真实客户首批 | 本地公开工具控制器做助手；独立 LLM 做客户；040、031、001、049、036 | 两侧各一次，共 10 episodes | 先做 040 双侧的 2 次，检查实际 token、协议和审批行为，再完成其余 8 次；2 次包含在 10 次内 |
| A2 可选扩展 | 021、014、006、007、002，覆盖长流程 | 另 10 episodes | 先免费实现这些题的自适应控制器；分析 A1 后单独批准 |
| A3 可选全覆盖 | 余下 40 题 | 另 80 episodes | 先完成控制器开发；与团队确认独立真实客户验证的覆盖要求。A1+A2+A3 合计 100 次，不重复计算 |
| B0 正式 parity 预检 | 原生 HTTPAgent 与 Harbor 对应 relay；助手、客户均为真实模型；上述 10 题 | 20 episodes | 先前 5 题双侧，再长流程 5 题双侧；两段使用相同配置才属于同一预检 |
| B1 完整第一轮 | 全 50 题，原生一轮、Harbor 一轮 | 100 episodes | 双侧预检通过、长题实际费用已校准、获得本阶段预算 |
| B2 补齐三轮 | 原生 r2 → Harbor r2 → 原生 r3 → Harbor r3 | 200 episodes | 双侧第一轮已完成，无未解决的适配偏差 |

B0 与完整成绩分开；B1+B2 为 300 次完整实验，加预检共 320 次。不是先在一侧跑完三轮。
首批 10 题是按交互类型、流程长度预选的诊断集合，不用于宣称总体统计代表性。
如果团队批准正式 parity 子集，需要另定选样方案并支持 `--split parity`，不能自动拿诊断集合代替全量。

Harbor 规范要求协调模型、轮数与 API 配置，并按双侧预检、双侧完整一轮、双侧三轮推进。
“独立 LLM 客户 oracle 全覆盖”是本 benchmark 的验证范围议题，并非所有 Harbor 适配器统一要求。
自定义 agent 场景还涉及标准 agent 的补充比较，是否适用及其规模必须向团队确认，尚未计入下方预算。
来源：[Harbor adapter 规范](https://github.com/harbor-framework/adapters/blob/main/docs/adapters.mdx)。

## 候选模型与运行配置

| 角色 | 候选 | 输入 / 输出，美元每百万 tokens |
| --- | --- | --- |
| 客户 | `gpt-5.4-mini-2026-03-17` | $0.75 / $4.50 |
| 业务助手（组合一） | `gpt-5.4-2026-03-05` | $2.50 / $15.00 |
| 业务助手（低价组合二） | 与客户同版本的 GPT-5.4 mini | $0.75 / $4.50 |

价格于上述日期查阅官方模型页；采用常规文本单价，不预扣缓存折扣。
官方列出这两款模型支持 Chat Completions、函数调用和流式输出；账户访问权及实际线协议仍需验证。
来源：[GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini)、[GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4)。

拟议并发 1、整题自动重跑 0；保留原生 seed=0、send_seed=false、max_errors=16、整题 5400 秒、请求 600 秒。
拟议客户每请求最多 4096 输出 tokens、reasoning=none；助手最多 8192、reasoning=low；temperature 保持 null。
这些上限与原生示例的 393216/262144 不同，须明确记录，并在两侧逐角色保持一致；不能悄悄沿用离线 fixture 的 900 秒时限。
一旦输出截断或上下文超限，先分析，再以新配置版本对称复验。

原生 transport 当前发送 `max_tokens`。真实供应商字段支持、推理参数、usage 返回及上下文恢复语义需核实；若需兼容映射，只能在双方一致的 transport 层实现并记录。
不能仅因为模型页写着支持 Chat Completions，就宣称当前运行器已经兼容。
真实客户仍使用原生客户策略，不注入脚本答案；自由表达与结构化回执之间的适应性正是 A1 要验证的内容。

## 预算估算及依据

原始数据见 `budget-estimate.json`，复现脚本为 `../scripts/estimate_live_budget.py`。
它只读取此前保存的 API 请求，统计 messages 与工具 schema 长度，不执行模型、原生业务或 grader，也不输出消息正文。
5 题使用最新自适应脚本轨迹，其余 45 题使用已选定的旧线性脚本轨迹。

当前没有真实 usage；本机也没有可离线使用的目标 tokenizer 资源。因此输入采用 **UTF-8 序列化字节数 / 3** 的粗略代理，逐请求累计重复历史。
输出另假设每个客户请求计费 512 tokens、每个助手请求计费 1536 tokens（作为含推理的预算占位），不是脚本的零 usage。
公式：`费用 = 输入 token 代理 × 输入单价 / 1e6 + 假设输出 tokens × 输出单价 / 1e6`。

单侧 50 题脚本日志有客户请求 2558 次、助手请求 8435 次；对应累计输入代理约 3147 万和 4.131 亿 tokens。
首批 5 题单侧客户仅 187 次请求，输入代理约 183 万 tokens。长题与反复发送历史使全量成本不能按首批五题简单乘十。

“基线”沿用这些请求规模；“压力情景”将输入、输出都乘 3，再加 25% 失败尝试预留，即基线的 3.75 倍。
**两列是情景测算，不是置信区间、实测账单或保证不会超过的上下界。** 实际模型可能更早失败，也可能增加很多轮。

| 范围 | 基线 USD | 压力情景 USD |
| --- | ---: | ---: |
| A1 客户验证首批 5 题，10 次 | 3.60 | 13.51 |
| A2 客户验证扩展 5 题，另 10 次 | 11.37 | 42.63 |
| A3 客户验证余下 40 题，另 80 次 | 44.02 | 165.09 |
| A 全 50 题客户验证合计，含 A1/A2 | 59.00 | 221.23 |
| B0 前 5 题双侧预检，组合一 | 82.56 | 309.59 |
| B0 全 10 题双侧预检，组合一，含前 5 题 | 839.17 | 3146.89 |
| B1 双侧完整第一轮，组合一 | 2513.32 | 9424.95 |
| B2 双侧追加两轮，组合一 | 5026.64 | 18849.90 |
| B 总计 320 次，组合一 | 8379.13 | 31421.74 |
| B 总计 320 次，双方都用 mini 的组合二 | 2648.11 | 9930.42 |

两套 B 是备选方案，不能相加；A 全覆盖已含首批，也不能再加 A1。两套 B 都只包含一个被测助手模型组合，不含额外标准 agent 比较。
组合二的 B0 前 5 题约 $27.29 / $102.33；完整 10 题约 $262.23 / $983.37。
模型选择还要考虑能否产生有意义的业务表现，不能单凭低价格选定。

估算不含税、云机器、第三方网关加价、区域处理附加费或长上下文加价；未假设缓存命中、Batch 优惠或团队折扣。
GPT-5.4 官方对超过 272K 输入 tokens 的会话另有加价规则。当前缓存最长请求约 513 KB，真实轨迹增长后仍可能触及阈值，届时重算，不能把压力情景当硬上限。
API 工具均为本地业务工具，本方案没有购买供应商搜索、文件检索等附加工具。

**预算建议：只拟议 A1 上限 $25；B 先申请团队资源和首批预检额度，取得实测后再分阶段审批。**
缓存折扣可能显著降低长历史费用，但不能在取得真实 usage 前把它当成确定节省。

## 隔离、停止与结果记录

助手只能访问公开消息与业务工具；客户只能按原生客户策略使用自己的门户工具。两者都不获得 grader 或隐藏评分条件。
助手停止后从可信业务环境收集证据，另起隔离 verifier 评分；grader 禁网、无模型凭据，运行中不将分数反馈给助手。
脚本客户证据、真实客户 oracle、正式模型 parity 分目录记录；保留 G/P/F/Strict、每次尝试、usage、成本、配置哈希及失败原因。
真实失败保留，基础设施错误分列，不挑选最佳尝试，不因客户拒绝而强行批准。

启动前还需完成真实客户入口（现有 adaptive runners 仅支持脚本 fixture）、可验证 Harbor 源码 pin、参数映射和费用控制。
费用控制必须按请求预留“输入费用 + 最大输出费用”，把所有原生重试纳入同一账本；后台预算提醒不能当作硬限额。
80% 额度时不再排新题并复核；剩余额度不足以预留下一请求时停止发送。预算中断的实验保留未完成原因，不能冒充完整 parity。
若无法实现可执行的网关/供应商限额与本地请求控制，就保持不启动。这个控制尚未实现，本文不声称已有硬预算保护。

模型/配置哈希不一致、隔离破坏、grader 异常或不明 API 失败时停止扩大实验。
真实模型同题结果不要求逐项完全相等；正式统计使用三轮均值及 sample SEM，按 Harbor 规范比较两侧 run-score ranges，并分析系统性差异。
先取得 A1 的真实 token、拒绝/澄清频率、截断情况及完成率，更新预算后再考虑下一阶段。
